# 变更日志

本文件记录梵禾 Work 的对外可感知变更。0.x 阶段版本号仍按 SemVer 解释，但**「破坏性变更」的含义是「升级时需要额外动作」**，不一定是接口不兼容 —— 例如必须跑一条迁移、必须重打安装包、手工加过的角色授权会被重置。

历史版本的详细方案见 `docs/RELEASE-<版本>.md`；更早的迭代过程见 `docs/WORK-STATUS.md`。

---

## [0.2.0] - 2026-10-20

一个模块级的新增：**运营看板**。千牛 / 生意参谋的经营数据接进梵禾 Work，成为运维信息平台下的七个入口，并打通了「每日采集 → 入库 → 看板可见」的完整链路。首页「全部品类」弹窗同时收敿为九品类网格。

### 新增

- **运营看板模块（七个入口）**：数据大屏、交易分析、商品分析、流量分析、服务体验、推广投放、内容运营。侧栏点左侧换右侧整块看板，区间与店铺写进地址栏（可分享、可刷新、后退符合直觉）。
- **数据接入**：`ecom_shops` / `ecom_daily_metrics` / `ecom_dimension_snapshots` / `ecom_collect_runs` 四张表与四个枚举，一条迁移（第 8 个）。
- **五个接口**：`GET /api/ops/dashboard`（单店读模型）、`GET /api/ops/overview-shops`（五店并列带）、`GET /api/ops/health`（采集批次与新鲜度）、`GET /api/ops/shops`、`POST /api/ops/ingest`（回环 + 共享密钥写入）。
- **三个权限点**：`ops.shop.read`（进入看板）、`ops.finance.read`（金额类指标）、`ops.collect.read`（采集批次）。页面准入与金额可见分开授权。
- **采集器迁入**：`tools/collector/` 收下 30 天基线（17 个模块、67 张 CSV）、20 个采集与校验脚本、10 份口径文档与一份前端原型页面，作为后续持续开发的依据。
- **日增适配器**：`tools/collector/scripts/export-daily-ingest.mjs`，把 `data/daily/<日期>/` 的原始响应转成入库契约，并输出逐块的覆盖率报告。
- **回填入口**：`pnpm db:ops-import [契约 JSON 路径]`，与 HTTP 写入共用同一个 `ingestOpsSnapshot`。
- **五店并列与占位**：`pnpm db:ops-shops` 建 `s2`–`s5` 四家「已登记、无数据」的店，未接入店显示「待接入」与「—」而不是被隐藏。
- **涨跌色令牌** `--up` / `--down`（亮暗各一份，涨红跌绿），与「危险操作」的 `--destructive` 分开。

### 变更

- **导航清单 18 → 21 项**：运维信息平台由「1 个入口 + 3 个功能开发中槽位」改为七个具名入口，预留槽位 11 → 8 项。
- **「数据看板」改名为「数据大屏」并绑定 `ops` 模块**：此前它对所有已认证用户可见，现在需要 `ops.shop.read`。
- **首页「全部品类」弹窗**：从「27 个占位案例位 + 10 个筛选芯片」改为 3×3 的九品类网格，卡片样式与主页横滑条逐项对齐。`CaseSlot` 类型保留、当前为空数组，案例库建立时换一次查询即可接真实数据。
- **维度快照的选择规则**：从「取 `statTo` 最新」改为「取与查询区间重叠天数最多」，否则日增的单日快照会把「近 30 天」的商品榜顶成「最新一天 Top 5」。
- **区间档解析**：地址里只写 `from` / `to` 时按「自定义」理解，不再静默回落近 30 天。
- **区间锚点**：以库里最新一天为锚，不以「今天」为锚（采集是攒出来的，以今天为锚会让首屏多出几天空白）。
- **`docker-compose.yml` 增 `OPS_INGEST_TOKEN`**：默认空，为空时写入接口返回 503 并说明原因，读接口与页面不受影响。

### 修复

- **金额裁剪与权限脱钩**：首版把 `maskDimensionRows` 写在取数路径上，导致持有 `ops.finance.read` 的账号也看不到商品与渠道金额，而 KPI 正常 —— 只测 KPI 的用例全绿。现按权限判断，并补了「有权限时金额必须在」的反例。
- **起止颠倒的区间返回一屏空数据**：现在直接 400 并说明哪一端在前。
- **从 `/login` 登录成功后落进 404**：登录页不在路由表里，登录成功后地址仍是 `/login`；补了 `login` / `setup` 的兜底重定向。
- **没有金额权限时商品表仍显示空的「加购金额」列**：金额列改为各自判断，键被裁掉就整列不渲染。
- **没有采集权限时仍发一次注定 403 的请求**：按 `can()` 门控，面板改为直接渲染「无权限」说明。
- **单日查看声称「这段时间没有可画的逐日数据」**：实为只有一格、画不出线。改为给出四项读数并说明原因。
- **全零序列的柱状图纵轴标成「¥0.01」**：`seriesCeiling` 的兜底值 1 分被直接格式化。全零时标 0。
- **五店迷你柱被峰值压平**：柱高改按平方根压缩（仅这条 16px 装饰带），读数仍由悬停给出精确值。
- **内容来源访客在空集合时显示 0**：改为「待接入」，与「真的为零」区分。

### 优化

- 未接入的服务 / 推广 / 内容三个板块显示「缺哪几个数、在哪个后台、卡在第几批」，不给演示数字。
- 趋势图支持按指标切换，四指标折线可逐条开关；各曲线按自身峰值归一，只比趋势不比高低。
- 采集器整体加入 `.gitignore` / eslint `ignores` / `.prettierignore` 三处，保持与采集源字节一致。
- 运营看板配套文档：`docs/ops/README.md`（模块边界、权限、口径、欠账）、`docs/ops/DATA-CONTRACT.md`（上报契约）、`docs/ops/RUNBOOK.md`（每日采集、回填、故障判据）。

### 破坏性变更 / 升级须知

1. **必须应用第 8 个迁移并重跑种子**。容器部署时 `migrate` 服务也要重建：`build migrate api web` 三者一起。只重建 `api` / `web` 会让旧镜像的种子按旧权限清单把新增的 `ops` 授权摘掉（实测日志「移除授权关联 6」，随后管理员访问看板 403，而 `permissions` 表里三个新点在）。
2. **角色授权以代码为准**。重跑种子会删除手工加在**角色**上的额外授权（`user_permissions` 账号级授权不受影响）。给某个账号单独开运营看板请用账号级授权。
3. **`/ops/slot-1` `/ops/slot-2` `/ops/slot-3` 三条地址不再存在**（导航项删除），旧书签会落到「页面不存在」。
4. **成员与访客默认看不到运营看板**。此前占位入口对所有已认证用户可见，现在需要 `ops.shop.read`；管理员与 owner 默认已具备。
5. **桌面端必须重打安装包**。`app.getVersion()` 读的是被打包进去的 `package.json`，只改仓库根版本而不重打包，客户端仍会自称 `0.1.6`，更新通道会反复提示有新版。
6. **全新部署要跑 `pnpm db:ops-shops`**。五店并列依赖这四行占位记录；不跑也能用，但首屏只有一家店的卡片。

### 已知限制（不影响升级，但会影响读数）

- 服务 / 推广 / 内容三个板块**没有真实数据**，页面显示待接入清单。
- 日增的**渠道块经常缺失**：当天的 `flow-shopsource` 只采到总览、没有渠道树时，渠道排行会是空的，报告里会写明「未采到渠道树」。
- **多日区间的 KPI 会从「整段去重」退回「逐日求和」**：`period` 只在查询区间恰好等于某个快照窗口时生效。日增开始后 30 天区间与快照窗口错开一天，访客会从 3,890 变成 4,069（跨日重复访客被重复计），金额不变。这是口径切换，不是增长，KPI 卡上的徽标会标明。
- **日增未接入计划任务**：`run-daily.ps1` 不自动调用导出与入库，两步需人工（或计划任务）接着走。
