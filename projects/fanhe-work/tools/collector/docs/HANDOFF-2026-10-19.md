### 2.3 为什么采集靠 Edge 调试端口

生意参谋有 baxia 风控。页面内注入的 `fetch` 与 `XMLHttpRequest` 一律返回 `TypeError: Failed to fetch`，隔离世界同样失败。唯一可行路径是让页面自己发请求，我们在 CDP 的 Network 事件上旁路截取响应体。

```
PUT /json/new?<目标页 URL>        新建标签并导航
WebSocket 连 webSocketDebuggerUrl
Network.responseReceived         记下 requestId
Network.loadingFinished          等响应完整
Network.getResponseBody          取回响应体落盘
```

### 3.8 采集口径变更：只做日增（2026-10-20）

用户明确：**所有数据源只抓「前一天」，不做历史回溯**；抓完由使用方自行做增量存储，采集端不承担去重与合并。

- 新脚本 `scripts/collect-daily.mjs`。目标日期默认前一天，`--date YYYY-MM-DD` 可覆盖；输出 `data/daily/<日期>/<模块>/NN_<接口>.json` + `_manifest.json`
- **单标签顺序导航**：生意参谋 SPA 有路由守卫，直接开新标签到 `/qos/**` 会被弹回「数据概览」首页（多次复现）。必须先落首页让 SPA 启动，再用页内 `location.href` 跳转
- **契约边界**：采集端不去重、不合并、不碰 `data/raw30`、不调用 `build_csv.py`。`build_csv.py` 的「按 URL 去重 + 全量重建」属于存储端职责
- 实测 2026-10-19 的 qos-core：20 个接口，三分钟人工响应率 100%、平均响应时长 22 秒、咨询人数 3、接待人数 3
- `data/daily/` 已加入 `.gitignore`，不进版本库
- 旧的 `collect.mjs` 保留，用于复现 30 天基线（`csv30` 的来源）

### 3.9 日增链路全量验证（2026-10-20 下午）

把 13 页清单补到 **17 页**（补 `content-live` / `content-channel` / `qos-experience` / `qos-performance`，它们在 `csv30` 里本来就有正常产出），并对 2026-10-19 跑了两轮全量，得到的四个结论都是踩出来的：

- **`dateType` 只有 `day` 是对的**。`recent30` 看起来「能用」，实际会被页面把区间改写成「终点往前 30 天」：传 `dateRange=2026-10-19|2026-10-19` 进去，页面地址栏变成 `2026-09-20|2026-10-19`，拿回来的是 30 天口径。判据是页面上那行「统计时间」，用 `day` 时会精确写 `统计时间 2026-10-19`
- **等待时间不够是第一轮大面积空采的真正主因**。第一轮每页等 32 秒，`trade-detail` / `trade-refund` / `flow-overview` / `item-macro` / `content-overview` 五页各只拿到 1 个接口 183 字节 —— 那是全局心跳 `ipoll/activity/getCurrentTime`，业务请求一个都没发。拉到 60 秒后 `trade-refund` 1→37、`content-overview` 1→6、`trade-detail` 1→8，`flow-overview` 单页实测能发到 `flow/new/guide/trend`、`flow/v3/overview/shopFlowSourceTop/v4`、`flow/new/overview/pageFlowTop` 等十余个业务接口。**默认值已改成 60000**
- **「页面被弹回首页」和「页面开着但没发请求」要分开判**。`_manifest.json` 里每页记了 `bodyHead`，面包屑停在 交易 / 流量 / 商品 / 内容 / 服务 就说明路由是通的，问题在数据没加载，不要去改导航方式
- **`trade-detail` 有两条会失败的子请求，可以忽略**：`fa/config/voucher/getInitAccountDate` 返回 code 1000、`fa/trade/tradeIntegrityDiagnose` 返回 code 1009（`validate end date error, Params:statDate=2026-10-18, endDate=2026-10-19` —— 这条子接口只支持到 T-2）。主数据 `bda/tradinganaly/overview/get_summary` 正常返回单日值

新增三个配套脚本：

| 脚本 | 作用 |
| --- | --- |
| `scripts/run-daily.ps1` | 一条命令完成「启 Edge → 等端口 → 跑采集 → 收尾」。**只杀命令行里带本项目 `.browser-profile` 的 msedge**，不动你手动开的窗口。参数 `-Pages` / `-Target` / `-Wait` / `-Boot` / `-Script` / `-ScriptArgs` |
| `scripts/probe-page.mjs` | 单页探针。输出页面标题、地址、**统计时间原文**、iframe 列表、以及本次导航的**全部** XHR/Fetch（业务域与其余分开列）。用来判断「页面到底有没有发请求」 |
| `scripts/check_daily.mjs` | 日增门禁。按页判 PASS / WARN / FAIL（FAIL = 0 个文件；WARN = 只有 1 个文件或 < 800 字节），并把非成功 code 分成「已知无害」与「需注意」两类。有空采页面时退出码 1 |

另外两个必须知道的约束：

- **采集器不能删文件**。本机 node 被注入了 safe-delete shim，单轮删除超过 50 个直接抛 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`；17 页一天约 150 个文件，整轮会中断在同一位置。现在的做法是把旧目录 `renameSync` 挪进 `data/daily/.trash/`（改名不算删除），再由 `run-daily.ps1` 采集结束后尽力清理
- **页面加载本身不稳定**，同一页单跑能拿 8 个接口、排在长队里只有 3 个。采集器因此内置偏薄判定（< 2 个文件或 < 800 字节）与最多 2 次重试（重试等待 `WAIT + 30s`），退出码 2 表示重试后仍偏薄

```powershell
# 全量抓前一天
powershell -ExecutionPolicy Bypass -File scripts/run-daily.ps1
# 只抓两页、指定日期
powershell -ExecutionPolicy Bypass -File scripts/run-daily.ps1 -Pages trade-detail,qos-core -Target 2026-10-19
# 探针看某页到底发了什么请求
powershell -ExecutionPolicy Bypass -File scripts/run-daily.ps1 -Script probe-page.mjs -Pages flow-overview -ScriptArgs "--wait 60000"
# 抓完复核
node scripts/check_daily.mjs --date 2026-10-19
```


## 四、关键决策与理由

| 决策     | 结论                      | 理由                                               | 影响                                           |
| ------ | ----------------------- | ------------------------------------------------ | -------------------------------------------- |
| 采集方式   | CDP 旁路录制                | baxia 风控封死了页面内注入取数                               | 必须保持一个带调试端口的 Edge 常驻                         |
| 大屏形态   | 与原页面一致的浅色，收进壳内          | 你的拍板。深色全屏与梵禾「方案 B 现代极简」令牌冲突                      | 删除全部暗色样式与投屏逻辑                                |

## 七、踩过的坑（换机后可能重现）

1. **Edge 调试端口随进程退出即消失**。`netstat -ano | findstr 9222` 为空就是没在跑。
2. **后台存根会吞掉新参数**（仅影响采集，不影响截图）。机器上常驻一个 `--no-startup-window` 的 Edge 存根占着同一 user-data-dir，`Start-Process` 传的新参数不生效，9222 端口起不来。采集时可靠做法是在同一个工具调用内依次完成：停掉全部 msedge、用全新的 profile 目录启动、轮询 `http://127.0.0.1:9222/json/version` 直到 200、跑完、停掉进程。
   **截图已不走这条路**：`shots-all.ps1` 改用 `msedge --headless=new --screenshot`，不需要调试端口、不调 `Stop-Process`、不会关掉用户正在用的 Edge，profile 放 `%TEMP%` 不占工作区。
3. **沙箱里 bash 连不上 127.0.0.1:9222**，PowerShell 能连。采集与截图脚本一律走 PowerShell。
4. **连续多条截图串联时，后面的标签可能没吃上 URL hash**，截出来是上一次的状态。交付前必须逐张看图，发现不对就单条重跑。
5. **极高视口截图会平铺错乱**。1680×2100 配 deviceScaleFactor 2 时，截图出现四宫格重复且内容空白。视口高度要贴着内容实际高度走。
6. **百分比高度在 flex 里会归零**。五店堆叠趋势一开始整块空白，原因是 `.stack` 用了 `align-items:flex-end`，`.stack-group` 没有确定高度，子元素的百分比高度全部解析为 0。改成 `align-items:stretch` 解决。
7. **堆叠趋势悬停报错**。`pageOverview` 崩溃在 `x.map.get`，原因是构造 tooltip 时误用了 `list`（只有 `{s, m}`）而非 `maps`（`{s, map}`）。
8. **CDP 脚本用 `Page.navigate` 后拿不到 DOM**。返回值稳定是 about:blank。改用与 `shot.mjs` 相同的链路（建标签时直接带 URL，不做二次导航）才稳。
9. **命令行空参数被吞**。PowerShell 传空字符串会丢参数，导致脚本把表达式当文件名，在工作区根目录写出垃圾文件。空参数一律用 `-` 占位。本轮产生的 3 个垃圾文件已清理。
10. **内容板块接口抓到但不渲染**。生意参谋内容模块抓了三次都没出数据面板，所以 v3 的内容三项指标改从光合平台取。

## 十一、可直接复用的命令

```powershell
# 只在开头定位一次工作区根，后面全部基于它。换电脑只改这一行，其余不动。
$root = "E:\qianniu-shuju"      # 当前这台；另一台改成 F:\qianniu-shuju

# 启动带调试端口的 Edge（采集用）
& "$root\start-edge-debug.cmd"

# 全量抓 30 天数据（先确保 Edge 已登录生意参谋）
$env:OUT_ROOT = "$root\data\raw30"
$env:DATE_QS  = "?dateType=recent30&dateRange=2026-09-19%7C2026-10-18"
node "$root\scripts\collect.mjs"

# 单页截图（宽 高 必填，第 5 个参数传 full 走整页）
node "$root\scripts\shot.mjs" "$root\preview\ops-dashboard-preview.html#/trade?g=day&p=30d&cmp=0&q=80000&s=main" "$root\preview\x.png" 1680 1500

# 一键跑 11 张截图（无头模式，不启调试端口、不关你正在用的 Edge，无需传路径）
# 只做路径自检不截图：加 -Check
powershell -NoProfile -ExecutionPolicy Bypass -File "$root\scripts\shots-all.ps1"

# CSV 转 XLSX 报表（三个 Python 脚本的输入输出目录都由脚本自身位置推导）
# 注意：必须用装了 openpyxl 的隔离虚拟环境解释器，系统 Python 没有这个包
& "$env:USERPROFILE\.workbuddy\binaries\python\envs\default\Scripts\python.exe" "$root\scripts\build_xlsx.py"

# 日增采集：只抓前一天，输出 data/daily/<日期>/，不做去重与历史合并
node "$root\scripts\collect-daily.mjs"

# 从 csv30 重新生成页面数据（默认预演；加 --write 才落盘；写完必须跑 check_data）
node "$root\scripts\build_preview_data.mjs" --write

# 页面数据与 csv30 对账（11 组常量 + 四个金额锚点，失败退出码 1）
node "$root\scripts\check_data.mjs"

# 大屏切店一致性门禁（58 条断言，失败退出码 1，改动页面后跑一次）
node "$root\scripts\check_store_switch.mjs"
```

不想维护 `$root` 时，直接在工作区根目录打开终端，用相对路径 `.\scripts\shots-all.ps1` 也可以，脚本内部照样能定位到自己。
