## 四、字段结构对齐

### 4.1 命名约定（沿用现有）

| 后缀 / 前缀  | 含义               | 例                               |
| -------- | ---------------- | ------------------------------- |
| `Uv`     | 去重人数             | `itmUv` `flowRecUv`             |
| `Cnt`    | 计数               | `payByrCnt` `violationCnt`      |
| `Amt`    | 金额               | `payAmt` `kwCost`               |
| `Rate`   | 比率（0–1 小数，不存百分号） | `payRate` `csThreeMinRate`      |
| `Sec`    | 秒                | `csFirstRespSec`                |
| `Score`  | 评分               | `itemBaseScore`                 |
| `Status` | 枚举               | `protectStatus` `actJoinStatus` |
| `Crc`    | 环比（0.05 = +5%）   | `payAmtCrc`                     |

### 4.2 快照结构（解决区间重算）

现有 CSV 是「一次导出 = 一个区间聚合」。要让 20 项新指标支持日 / 周 / 月 / 年与任意区间，落库必须按天：

```
ecom_metric_daily
  shop_id        店铺 id
  stat_date      统计日
  metric_key     指标键（上表字段名）
  value_num      数值
  value_text     枚举值（protectStatus / actJoinStatus 用）
  source         来源标记（sycm / qianniu / wxt / guanghe / mkt / protect）
  collected_at   采集时间
  唯一索引 (shop_id, stat_date, metric_key)
```

这样 KPI 卡才能标「逐日」而不是「整段」。前端页面上标注的三档口径（逐日 / 折算 / 整段 / 演示）在数据齐了之后可以全部收敛成「逐日」。

### 4.3 店铺维度预留

5 家店铺 = 5 套登录态。`shop_id` 必须进表，且每个后台的 cookie 要按店铺隔离存放：

```
ops/credentials/<shop_id>/<source>.json     ← 各后台各自一份 cookie
```

主店用真实账号，分店 2–5 待你提供子账号或授权方式后接入。在此之前页面保持现在的「演示」标记。
