## 二、新的信息架构

```
运维信息平台
├─ 数据大屏          预览 5 家     ← 跨店总览，只有这一个入口
└─ 业务分析                        ← 分组线
   ├─ 交易分析
   ├─ 商品分析
   ├─ 流量分析
   ├─ 服务体验
   ├─ 推广投放
   └─ 内容运营
```

### 为什么这样分不重复

- **数据大屏**回答「五家店今天整体怎么样、哪家出问题」——五店金额 / 买家 / 转化并列，五条风险条，跨店对比，五店堆叠趋势。它不展示任何单店明细。
- **业务分析**回答「这一家店的这块业务具体怎么了」——每页都是单店深钻，页头写明当前店铺，顶栏右侧胶囊也能随时切店。
- 大屏底部的 6 张模块入口卡是**导航**，不是大屏自己在重复展示明细。点进去才是明细。

### 店铺切换

三处都能切，切完地址栏同步，分享链接口径一致：

1. 顶栏右侧店铺胶囊
2. 大屏五张店铺卡
3. 各业务页「各店 xx 指标」表格里点行

## 十、本轮三项调整（2026-10-19 晚，单日 + 切店 + 全页时间条）

### 10.1 单日区间

时间条在「近 7 天 / 近 30 天 / 本月 / 上月」前新增 **单日**，共 6 档（含自定义）。

- 单日默认落在 **2026-10-15**，即最后一个有成交的日子；数据尾部 10-16 ～ 10-18 确实是 0 单，若默认取 10-18 会整屏 ¥0，看起来像坏了。手动改到 10-18 仍会如实显示 0。
- **只有支付金额是当日真值**（来自 `DAILY` 逐日序列）。买家数 / 访客数接口只给 30 天聚合值，单日只能按 1/30 日均折算，所以：
  - 时间条右侧出现红色提示「单日：支付金额为当日真实值，买家 / 访客只能按 30 天日均折算」；
  - 大屏店铺卡、交易分析 KPI 徽标显示「折算」而不是「逐日」；
  - 大屏脚注追加一句单日口径说明。
- 金额为 0 的区间不再显示折算出来的买家（`¥0 · 买家 3` 这种自相矛盾的组合已修掉），买家直接归零。
- 单日 / 短区间下 **环比不再显示数字**，改显「仅 30 天口径」：环比本来就是 30 天对 30 天，短区间没有可比对象，显示 +70.1% 会被当成日环比。
- `p=d1` 也记在 URL 里；手工选某一天再刷新，日期不会丢（`readState` 对 d1 会读 a1/a2）。

### 10.2 业务分析六个板块都能切店

每个业务页页头右侧加了店铺分段控件（主店 / 分店 2-5，分店带黄点），切店后 URL 的 `s=` 变化、整页数据一起换：

| 页面 | 切店后变化的部分 | 实现 |
|---|---|---|
| 交易分析 | KPI、日明细、趋势图、月度限额全部换成该店日序列 | `SER` 指向 `storeSeries(s)`，`slice/buckets/quotaInfo/metrics` 统一走 `SER` |
| 商品分析 | 10 个链接的访客 / 金额 / 加购 / 收藏按该店倍率缩放 | 渲染前 `pushDemoStore` 缩放常量 |
| 流量分析 | 访客 / 商品访客 / PV / 渠道结构 / 地域 / 搜索词按倍率缩放，「其他」残差同步 | 同上 |
| 服务体验 | 咨询量、待回复、待答条数按倍率缩放 | 同上 |
| 推广投放 | 花费、余额、活动访客与金额按倍率缩放 | 同上 |
| 内容运营 | 内容查看、商品点击、各来源访客按倍率缩放 | 同上 |

机制说明（写代码时照这个思路落地）：

- 分店没有采集，所以 **不新建假数据集**，而是渲染前把主店常量按 `ratio` 就地等比缩放，渲染完 `finally` 还原。渲染是同步的，不会串页。
- 只缩放**计数类**字段（金额、访客、买家、加购、收藏、花费、条数）；**比率、时长、评分、活动状态不缩放**（`crc / rate / ratio / status` 这些键名直接跳过）。
- 缩放期间 `FORCE_DEMO = true`，整页 KPI 徽标统一变「演示」，不会出现分店页挂着「逐日 / 整段」这种真实口径。
- 页头店铺名后仍有「演示数据」标记；大屏页**不参与**缩放（它要同时看 5 家），只把当前店高亮。
- 交易分析页脚、商品分析页脚、推广投放页脚的「四处一致 ¥108,000」「付费访客 35 个」等主店口径断言，在分店页会自动替换成分店演示说明，避免拿主店结论套分店。

### 10.3 所有业务板块都有时间区间

> **2026-10-20 修订**：本节原文写「七个路由都常驻时间条」，实际造成三页出现假控件——服务体验、推广投放、内容运营的数据全是 30 天整段值，`pageXxx` 里根本不读 `st.a`，时间条点了只有高亮变、数值不变，用户会以为刷新失效。这三页已改为**不可交互的快照条**（`snapshotBar()`，只写「30 天整段快照 + 覆盖区间 + 口径说明」）。明细见 `docs/服务体验数据加载异常分析与整改-2026-10-20.md`。

四个能真正重算区间的页面（大屏 / 交易 / 商品 / 流量）仍常驻时间条，档位一致；每页用右侧 `tb-note` 说明本页的区间口径：

| 页面 | 区间口径 |
|---|---|
| 数据大屏 | 全区间可用；金额逐日精确，买家 / 访客按天数折算 |
| 交易分析 | 全区间逐日精确求和（唯一能逐日重算的页） |
| 商品分析 | 金额 / 访客 / 加购按覆盖天数等比折算，转化率与结构占比不随区间变；折算时表头标注「按 x/30 折算」 |
| 流量分析 | **不折算**：流量接口只给 30 天聚合值，渠道 / 地域 / 搜索词都是整段，为避免 KPI 与明细互相打架，整页统一整段口径 |
| 服务体验 / 推广投放 / 内容运营 | 数据只有 30 天整段值，**不提供区间控件**，页头改为快照条说明口径与覆盖区间 |

### 10.4 顺带修掉的分店数据可信度问题

- 分店倍率下调：分店 2/3/4/5 从 0.62 / 0.38 / 0.88 / 0.19 改为 **0.22 / 0.14 / 0.40 / 0.09**。原倍率下分店 4（¥117,510）比主店（¥108,000）还高，五店合计 369,290 而主店只占 29.2%，明显不像一个真实的五店结构。现在五店合计约 19.98 万，主店占 54.1%，且任何一天都不会出现分店超过主店。
- 分店日序列的「大促脉冲」判定跟着改成 `ratio ≥ 0.4`，只给分店 4 保留 10-08 的高峰，其余分店走日常波动。

### 10.5 已知取舍（下一步要么补采集、要么继续演示）

1. 单日 / 短区间的买家、访客仍是折算值，只有支付金额是真的。真正解决要在采集端按天落库（每天存一份），代码阶段做。
2. 流量分析坚持不折算，所以切到「单日」时 KPI 和明细都还是 30 天整段值 —— 这是刻意的，页面上已写明。
