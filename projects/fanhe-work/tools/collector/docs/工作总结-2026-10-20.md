## 一、已完成的主要任务与成果

### 1. 修复数据真实性：访客/买家改为逐日真值

**起点**：页面单日视图写着红字「买家 / 访客只能按 30 天日均折算」，用户要求直接体现抓取真值。

**核实结果**：支付金额本来就没被折算，真正的问题在更上游——**项目对接口能力的判断是错的**。`/flow/new/guide/trend.json` 一直返回 `data.my = { statDate[30], uv[30], payByrCnt[30], itmUv[30] }`，逐日数据从未缺失，就躺在 `data/raw30/flow-overview/04_trend.json` 里。丢失发生在转换层：`build_csv.py` 的 `convert_series()` 只识别 `lastDay` 结构，这个用 `statDate` 的结构落进了兜底分支，被压平成一行的 CSV。

**三层改动**：

| 层 | 改动 |
| --- | --- |
| 转换层 | 新增 `convert_statdate()`，按 `statDate` 展开一天一行，无 `statDate` 的分组按索引对齐；顺带固定 `lineterminator='\n'`、每模块重算前清空旧 CSV |
| 数据层 | 页面新增 `DAILY_FLOW` 常量与 `flowDaily(a,b)`；`metrics()` 增加 `basis` 三态（`daily` 逐日累计 / `agg` 整段去重 / `est` 分店折算） |

**顺带修正了一个业务结论**：此前认为 10-08 是流量高峰，实际那天访客仅 49 人，¥49,000 来自一笔大单；真正的高峰是 10-11 / 10-12（568 / 556 访客，各约 ¥3,000）。**流量峰与成交峰完全错位。**

**保留的口径差**：逐日求和 4,038 访客 / 92 买家 / 3,350 商品访客，整段去重 3,890 / 91 / 3,241。差值来自跨日回访重复，属合法差异，不再抹平，门禁有断言守住。

### 2. 大屏 #/screen 改造

**四指标折线图**（替代原堆叠柱图位置）：同时画支付金额 / 访客数 / 买家数 / 转化率，右上角四个勾选框可任意显隐，状态写入 URL 的 `ls` 参数。

核心难点是**量纲差两个数量级**（金额 0~49,000、访客 16~568、买家 0~7、转化率 0~10.2%），同轴必然三条贴底，双轴容不下三个量纲，对数轴读不了 0 值。最终采用**每条按自身区间峰值归一**，图注明确写「只比趋势不比高低」，页脚给区间合计、悬停给当日真值。折线另用实线/实线/虚线/点线做第二重区分。

**修复切店不刷新**：根因是数据绑定漏参数，四处把店铺钉死在主店（`trendRows` 遍历 `DAILY`、遍历 `DAILY_FLOW`、调用处不传店铺、页脚 `metrics(a,b,DAILY)`）。重渲染确实发生了，但输入没变，所以结果一样——这类缺陷不报错，比缓存失效更难发现。

修复时炸出一个取整事故：逐日 `Math.round(byr × ratio)` 让分店 5 的买家整月只剩 1 人（`round(4×0.09)=0`），正确值是 8。**逐日取整对小整数是系统性向 0 收缩，误差不抵消。** 改用最大余数法 `scaleAlloc`，四家分店实测 23→20、21→13、44→37、1→8。

**布局调整**：删除跨店对比表（七列里五项与五店卡同源），店铺卡改为「买家 · 访客 · 转化」三列，折线图从整行对比表腾出的空间横向拉长（viewBox 660×240 → 1000×250，单日 1000×140）。

**约定开例外**：大屏原规则是「切店任何数字都不变」，但单店折线图必须跟着店变。处理方式：门禁先剔除 `.chart-card` 再校验其余区块一致性，另加 7 条断言校验折线图确实随店刷新。

## 二、遇到的困难及解决方案

### 困难 1：一个错误结论支撑了整个折算逻辑

**表现**：页面把「没有逐日数据」当成既定事实，所有短区间数字靠 30 天日均折算。

**根因**：判断只到接口层就停了，没查转换层。数据在 `raw30` 里完整存在，被 `convert_series()` 的兜底分支压平。

**解决**：新增 `convert_statdate()` 按 `statDate` 展开；此后「有没有数据」这件事以 `csv30` 的实际产物为判据，不以历史结论为准。

**方法论**：**「接口没给」与「转换时丢了」外观完全一样**，排查必须从原始响应一路走到 CSV。

### 困难 2：日增首轮 5 个页面各只采到 1 个 183 字节的响应

**表现**：`trade-detail` / `trade-refund` / `flow-overview` / `item-macro` / `content-overview` 全部只拿到一个响应，体积 183 字节。

**误判过程**（值得记录，因为两个错误方向都很有说服力）：

1. 先怀疑路由守卫弹回首页 → 查 `_manifest.json` 的 `bodyHead`，面包屑正确停在 交易/流量/商品/内容/服务，**排除**。
2. 再怀疑 `dateType` 参数不对 → 改成 `recent30`，`flow-overview` 从 1 个变成 3 个接口，看似有效；但 `trade-detail` 报 `code 1009 validate end date error`，且探针发现**页面把 `dateRange=10-19|10-19` 自己改写成了 `09-20|10-19`**——`recent30` 强制 30 天窗口，不能用于单日，**推翻**。
3. 真因是**等待时间不够**。32 秒时业务请求一个都没发，只采到全局心跳 `ipoll/activity/getCurrentTime`；拉到 60 秒后 `trade-refund` 1→37、`content-overview` 1→6、`trade-detail` 1→8。

**解决**：默认等待改 60000。同时在 `probe-page.mjs` 里加了「统计时间原文」这一项输出——它是判断口径的唯一硬判据（`dateType=day` 时精确写 `统计时间 2026-10-19`）。

### 困难 3：采集器被本机「安全删除守卫」拦停

**表现**：全量跑到某个位置突然退出，报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`。

**根因**：脚本每页先删旧 json，单轮删除超过 50 个就触发。17 页一天约 150 个文件，必然中断，且中断点固定。

**解决**：改为把旧目录 `renameSync` 挪进 `data/daily/.trash/<日期>_<模块>_<时间戳>`，再建同名空目录——**改名不算删除**。`.trash` 由 `run-daily.ps1` 采集后尽力清理，清不掉不影响结果。

### 困难 4：Edge 调试实例活不过一次工具调用

**表现**：先在一次调用里起好端口，下一次调用就是 `ECONNREFUSED`。

**解决**：把「启动 → 等端口 → 采集 → 收尾」封进 `run-daily.ps1` 的单进程内。同时踩到并修正两个相关坑：不能 `Stop-Process -Name msedge`（会连带关掉用户自己开的窗口，须按命令行过滤）；PowerShell 取 32 位目录必须写 `${env:ProgramFiles(x86)}`，写成 `$env:ProgramFiles(x86)` 会被解析成 `$env:ProgramFiles` 拼字面量 `(x86)`，`Test-Path` 静默为假。

### 困难 5：越跑越差——测试方式本身污染了结果

**表现**：为收稳 `trade-detail` 反复跑，结果连一直健康的页面也崩了：`item-rank` 从 14 个接口掉到 2、`qos-core` 从 20 掉到 2。而换全新标签重试后立刻恢复 14 / 20。同一轮里 `qos-refund` 仍有 45 个接口 / 370 KB。

**结论**：不像脚本 bug，像**账号侧对高频访问的限流**。当天从 05:00 跑到 08:00 连开十来轮，后段数字不可信。

**解决**：采集器做成两种导航方式**交替重试**——奇数轮页内 `location.href`（健康时最快最稳），偶数轮全新标签 + `Page.navigate`（退化时能恢复）；`/qos/**` 例外，永远走页内跳转（直接开新标签会被路由守卫弹回数据概览首页）。

**更重要的教训**：**同一批页面不能在一天内反复跑。** 我中途一度怀疑脚本有 bug，实际是访问频率问题。这条修正了此前「`trade-detail` 是间歇性偏薄」的判断——它至少一部分退化是自己跑出来的。真正的验收必须是一次干净的单轮运行。

### 困难 6：工具链的静默失败（三个都不报错）

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 生成数据后页面白屏 | `rowsJoined` 行间只加换行漏了逗号，`[..]` 换行 `[..]` 被解析成下标访问 | 连接符改 `',' + nl`；靠先提交「只加标记不改内容」的检查点才敢放心回滚 |
| 三个文件整文件重写（最多 5,901 行 diff） | Python `io.open(p,'w')` 在 Windows 把 LF 转 CRLF | 改 `'wb'` 走字节；确认 `preview/*.html` 是 CRLF、`scripts/*` 是 LF |
| 截图只出 1 张就「失败」 | Edge 把「N bytes written」写 stderr，PS 5.1 在 `Stop` 模式下当致命错误（图其实已写成） | 调用前后临时降为 `Continue`；**判断依据要看产物是否存在，不能只看退出码** |

另有一个设计缺陷值得单独提：`_manifest.json` 原来是整份覆盖，补采两页就把当天手册抹成两页；`check_daily.mjs` 又只遍历 manifest，于是自检也跟着失明。已改成 manifest 按页名合并、自检以**磁盘目录**为准取并集。
