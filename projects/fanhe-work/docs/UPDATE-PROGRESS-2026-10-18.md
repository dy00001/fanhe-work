# 更新下载进度：显示什么、为什么这么算

> 2026-10-18 实施。范围：顶栏更新入口的下载过程可视化。关联 `apps/desktop/src/update.ts`（状态机）、`apps/web/src/lib/desktop-update.ts`（视图与格式化）、`apps/web/src/components/UpdateNotice.tsx`（渲染）。

## 一、需求与取舍

要显示五件事：已下载 / 总大小、百分比、实时速度、已用时间、预计剩余时间；并在完成与失败时给出明确状态；网速波动、暂停、中断时读数要跟得上；小屏不能顶出视口。

一个先决判断：**这些数字必须在渲染进程之外算**。原因不是性能，而是**可测性**。速度平滑、剩余时间、停住判定都是「输入一串事件、输出一串数字」的纯逻辑，放在组件里就只能靠真机发版复现，而这类 bug 的表现是「读数看起来正常但是错的」，手工点一遍根本看不出来。

所以分三层：

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 状态机 | `apps/desktop/src/update.ts` | 收 `electron-updater` 的事件，维护字节数、平滑速度、起止时间 |
| 视图 | `apps/web/src/lib/desktop-update.ts` | 状态 → 界面字段（大小文案、速度文案、已用/剩余、是否停住） |
| 渲染 | `apps/web/src/components/UpdateNotice.tsx` | 窄条常驻 + 点击展开详情面板 |

## 二、速度：为什么自己做平滑

`electron-updater` 的 `download-progress` 自带 `bytesPerSecond`，但它是上游自己窗口的均值，刷新节奏与我们不同步。直接显示会出现「800 KB/s 与 3 MB/s 交替」的读数，读起来像网络在抖。

做法：用相邻两次事件的 `Δ字节 / Δ时间` 算瞬时速度，再与上一拍做指数平滑（系数 0.35）。

- 系数偏大（0.8）压不住抖；偏小（0.1）在断流时要好几秒才归零，那几秒里界面显示一个不存在的速度。
- 采样间隔小于 200 ms 时不重算：分母太小会把速度放大成几十 MB/s，且只活一帧。
- **字节数没涨时不立刻归零**，让它按 EMA 衰减几拍。否则一次卡顿会把速度打到 0 再弹回来，比不显示更难看。

上游自报值只在**第一拍**作为初值使用（那时本地还没有两个样本）。

## 三、剩余时间：三个「不知道」的写法

`剩余 = (总大小 − 已下载) / 速度`。三种输入缺失时各自有明确含义，不能互相顶替：

| 情况 | 显示 | 理由 |
| --- | --- | --- |
| 速度未知 | `剩余 —` | 不写 0 |
| 速度为 0 | `剩余 —` | 写「剩余 0 秒」是一个比「不知道」糟糕得多的谎 |
| 总大小未知 | `剩余 —` | 只剩已下载量可显示 |
| 已下满 | `剩余 0 秒` | 这是确定值，不是缺失 |
| 估算超过 24 小时 | `剩余 —` | 该量级对用户没有决策价值 |

## 四、暂停与中断

**没有「暂停」事件可用**：`electron-updater` 不区分「慢」与「停」。判据只能来自时间：最后一次进度距今超过 3 秒即视为停住。

- 取 3 秒而不是 1 秒：进度事件约每秒一条，3 秒意味着至少漏了两拍；网络抖一下就把界面切成「已暂停」会让人以为下载坏了。
- 停住时**不再显示速度**，改成一个明确的状态词加一句说明（`已暂停 · 已用 00:18 · 等待网络恢复`），进度条转琥珀色。
- 已下满但还没收到完成事件时**不算停住**：那是上游还没发下一个事件，不是网络问题。
- 真中断会走 `error`：失败态保留已下载量，按钮文案变成「下载中断 · 重试」，悬停说明里带原因。

## 五、为什么详情面板要独立存在

顶栏那一行只有几十像素，够说「正在下载 v0.1.5 · 38%」，说不清「112 MB 的包下到 42 MB、现在 2.4 MB/s、还要 29 秒」。而这三件事正是用户判断「要不要等」的全部依据。所以：**窄条常驻，点开看详情**。

面板宽度取 `min(20rem, 100vw − 1.5rem)`，右对齐挂在窄条下方，小屏上不会顶出视口。窄条本身沿用原来的高度（`h-8`），与账号头像同一行对齐。

## 六、一个容易被忽略的坑：时间会停

轮询在内容没变时会保留同一个状态引用（`isSameUpdateStatus`），于是不会触发重渲染。而「已用时间」「剩余时间」「停住多久」这三样**不随状态变化，只随真实时间推进** —— 没有额外的时钟，一次卡顿会让「已用 00:18」永远停在 00:18，看起来像界面死了。

所以在 hook 里加了一个只在下载阶段开启的每秒时钟。空闲时不跑：顶栏每秒重渲染一次是白烧 CPU。

## 七、验证

- 状态机 22 项（新增 9 项）：上游速度只作初值、本地样本平滑、卡顿衰减不归零、总大小不被冲成 null、失败保留已下载量、完成态对齐到 100%、新一轮清掉旧字节数、日志行含大小与速度。
- 视图 31 项（新增 12 项）：1024 进制、时间格式、ETA 的四种 null、停住判定、下满不算停住、失败带进度、形状不对的字节事实整体归 null、字节数变化必须被视为新状态。
- 未覆盖：真实下载过程的外观。它只在一次真实更新里出现，需在装有旧版的机器上更新到新版时观察。
