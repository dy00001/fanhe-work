# 客户平台每日同步（2026-10-29）

把 Obsidian「客户聊天记录库」的最新状态搬进工作台。前端不需要改动就能看到新数字，
因为列表的「N 条消息」「最近消息」「活跃度」、详情页的消息条数与首末时间早就在读
这些列了 —— 缺的一直是「谁来更新它们」。

## 链路

```
17:00  自动归档客户聊天记录（WorkBuddy 自动化）
       └─ 重写 D:\Obsidian\个人知识库\客户聊天记录库\*.md（全量快照）

17:30  fanhe-customer-sync（Windows 定时任务）
       └─ tools\crm\sync-daily.cmd
          └─ pnpm db:customer-sync
             └─ apps/api/src/customer/sync.ts
                ├─ archive.ts      读 md，抽聊天事实（不碰金额）
                ├─ stage-rules.ts  看板 > 台账 > AI 的三层仲裁
                └─ 按 chatroom 更新 customers 表
```

**顺序不能反。** 17:30 必须晚于归档任务；跑在归档之前只会重读昨天的快照，任务照样
`exit 0`、日志照样写「无变化」，没有任何地方看得出来。

## 为什么 api 不能自己定时扫目录

api 跑在容器里，`docker-compose.yml` 里没有任何卷挂载，看不到宿主机的 D 盘。容器内的
定时任务永远扫出 0 个文件，而且是「成功跑完」—— 这类失败不留痕迹。所以同步只能由
宿主机侧发起，与运营看板「采集机跑完 POST 进来」是同一个约束。

## 手动补跑

```bat
cd projects\fanhe-work
tools\crm\sync-daily.cmd                 :: 写库
tools\crm\sync-daily.cmd --dry-run       :: 只算不写
tools\crm\sync-daily.cmd --verbose       :: 列出每个客户的每一处变化
```

换一个聊天库目录（换机、或库搬了位置）：

```bat
cd apps\api
node_modules\.bin\tsx src\tools\customer-sync.ts --dir "E:\某处\客户聊天记录库" --dry-run
```

日志：`projects\fanhe-work\data\customer-sync.log`（已被 `.gitignore` 排除）。
定时任务没有控制台，失败的唯一证据就在这个文件里。

## 哪些字段跟，哪些必须挡

| 字段 | 处理 | 理由 |
|---|---|---|
| 消息条数、首末消息时间、图片/语音跳过数 | 无条件覆盖 | 聊天记录里的事实，重算永远比旧值准 |
| 来源群文件名 | 无条件覆盖 | 群改名后要跟着变，否则排障时对不上文件 |
| 客户阶段 | **有条件** | 只对「未复核 + 来源非人工/非看板」的客户跟 AI |
| 金额 | **绝不碰** | md 的 frontmatter 里那串数字是脏的（实测把手机号当合同额） |
| 订单与环节 | **绝不碰** | 来自看板的人工核验，不在这条链路上 |

阶段挡下来的客户会进报告的「阶段未跟」分类（已复核 / 人工来源 / 看板来源 / 无证据 /
与库里一致 / 空文件），**不静默丢弃** —— 否则「这个客户阶段为什么没跟着变」永远查不清。

## 三种「看起来没事」的失败

这三种都不会报错，所以写在这里：

1. **空文件。** 抓取偶发失败会留下只有 frontmatter 的 md，`msgRows = 0`。照着写下去
   会把一个聊了 628 条消息的客户清成「0 条消息、无最近消息」，而界面上它只是看起来
   「很久没说话」。防线是 `diffActiveFields` 在 `msgRows === 0` 时一格都不改，
   阶段也不判（残文件里的 `ai_stage` 可能是上一轮的旧值）。
2. **群文件前缀错。** 库里存的是 `上海树姐VIP设计沟通群.md`（带后缀），解析层若剥掉
   `.md`，每轮同步都会判定 53 条「全部有变化」。报告里永远显示「更新 53」，数字看着
   正常，真正的变化被埋得一点痕迹不剩。
3. **目录路径写错。** 扫出 0 个文件时**按失败处理**（退 1），不当作「今天没消息」。
   否则定时任务可以连续几周安静地什么都不做。

## 新建客户的规则

目录里有、库里没有、且不在别名表 `excludedGroups` 里的群，会自动建成**待复核**客户：

- 名字：群名剥掉 `VIP设计沟通群` 这类后缀，猜不准就整条留着（猜错会造出查无此人的
  客户，还会被拿去匹配看板与台账）；
- 地区：固定 `待确认`，不猜；
- 置信度：`none` 而不是 `low` —— 这里没有任何身份判断依据，要与「AI 抽出来待确认」
  的那批分开；
- 一条消息都没有的群文件不建（是抓取失败的残骸）。

排除清单在 `data/customer-aliases.json` 的 `excludedGroups`，目前排掉五个：展厅设计、
装修群-凉北天府苑、绿城沟通群、青海西宁刘姐Vip设计群、M世代积家。要收哪个就从这个
清单里删掉，下一轮同步会自动建进来。

## 文件删了不删客户

库里有、目录里找不到文件的客户只进 `missingFile` 报告，不删除。客户是资产，文件消失
可能是误删或换了存放目录；自动删除会让「客户清单少了三个人」在几个月后被当成从没
录过。

## 注册定时任务

```bat
tools\crm\register-sync-task.cmd              :: 双击，会请求管理员权限
tools\crm\register-sync-task.cmd -Remove      :: 取消
```

默认每天 17:30。沙箱内跑不了提权注册（`Access is denied`），必须双击一次。
