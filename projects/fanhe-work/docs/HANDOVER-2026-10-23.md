## 零、先看这五条（动了会出事）

| # | 红线 | 原因 |
| --- | --- | --- |
| 1 | **容器化之后采集走 DB 直连，不要指望 HTTP** | 宿主机经 `127.0.0.1:8787` 进来，容器看到的源地址是 docker 网关（172.x），`isLoopbackAddress` 判否 → `403 forbidden_origin`。这是那条校验的设计后果，不是配置错误。`sync-shops.mjs` 的 `--transport auto` 会自动降级 |
| 2 | **新增权限点必须重跑 `db:seed`，并重建 `api` 与 `migrate` 镜像** | owner 走代码常量仍有权限，内置「管理员」角色要靠种子才有该点。不重跑的表现是界面上少一个入口、零报错、库里全对 |
| 3 | **绑定会写 `tools/collector/shops.config.json`** | 真文件。集成测试必须设 `OPS_SLOTS_FILE` 指向临时文件，否则会留下测试店并把整份 JSON 重排（首版已踩） |
| 4 | **计划任务的「失败时重启」不覆盖外部杀进程** | 杀掉后任务停在 Ready、`lastResult=4294967295`、没有进程。现在靠「登录触发 + 每分钟重复触发 + 不启动新实例」看护。**重复触发器不能挂在登录触发器上**，那样 `NextRunTime` 为空、实际不触发 |
| 5 | **集成测试不要写运行时的单行状态行** | 心跳表主键是 `watch`，由常驻进程每分钟刷新。测试要验离线就得改它，直接共用会在 `after` 里把运行时那行删掉，界面随即显示「采集器从未启动」（首版已踩）。现用 `OPS_HEARTBEAT_ID` 指向独立 id；槽位表同理用 `OPS_SLOTS_FILE` |
| 6 | **`tsx.cmd` 内部调的是裸 `node`** | 交互式终端 PATH 有便携运行时，计划任务里没有 → 待办读不出、心跳写不进，界面只显示「采集器离线」。修法是把 `path.dirname(process.execPath)` 前置到子进程 PATH。同理，带空格的路径 spawn `.cmd` 必须自己加引号，`shell:true` 不会替你加 |

## 一、这一轮加了什么

### 1.1 店铺绑定入口

在运营看板顶部新增折叠面板（仅持 `ops.shop.bind` 可见）：填代号、名称、端口、掌柜即可登记一家店。

绑定做三件事：写 `ecom_shops`（`bound_at` / `login_state` / `collect_port` / `sync_requested_at` 等 6 列）、尝试写采集槽位、置 `sync_requested_at`。**不做采集** —— API 可能跑在容器里，碰不到宿主机 Edge。

- 落点：`apps/api/src/ops/shop-binding.ts`、`shop-slots.ts`、`routes/ops.ts`、`apps/web/src/components/ops/OpsShopBindingPanel.tsx`
- 迁移：`20261022145529_add_ops_shop_binding`

### 1.2 绑定后自动同步

`tools/collector/scripts/sync-shops.mjs` 轮询待办，跑既有采集与入库，回写登录态与失败原因。

- `--transport auto|http|local`，auto 遇 401/403/503 自动切 DB 直连
- `--watch 60` 常驻；`--dry-run` 只看待办
- 失败分类：端口不通 / 退出码 3（登录失效）/ 退出码 4（页面没加载）/ 导出失败 / 入库被拒 / 槽位缺失，各自一句可执行的话

### 1.3 采集器心跳

面板顶部显示「采集器在线 / 离线 / 从未启动」。

心跳不设独立接口：**拉待办这个动作本身就是存活证明**，HTTP 与 DB 直连两条路各写一次 `touchCollectorHeartbeat`。窗口 180 秒（容忍两次丢拍），判定函数 `isCollectorOnline` 在共享包，阈值只写一处。

- 迁移：`20261022153844_add_ops_collector_heartbeat`（单行表）

### 1.4 链路自检

```
cd tools/collector && node scripts/doctor.mjs
```

把「没有数」的五种可能拼成一张表：槽位 / 端口 / 浏览器可达 / 登录态 / 最近采集 / 待办 / 备注。

判定分两级：**阻断**（退出码 1，会让已请求的同步永远等不到结果）与**提示**（退出码 0，下次采集前处理）。采集浏览器凌晨没开是正常的，把它当阻断会让工具每晚报警，几次之后被无视。

### 1.5 常驻任务

| 文件 | 职责 |
| --- | --- |
| `tools/collector/start-sync-watch.cmd` | 找 node、单实例、日志轮转、ISO 时间戳 |
| `tools/collector/watch-guard.ps1` | 单实例判定（cmd 的 `for /f` 装不下管道 + 带引号的 `-Filter`） |
| `tools/collector/install-sync-task.ps1` | 注册 / 状态 / 移除计划任务 |

## 二、当前运行状态（本机实测）

- 计划任务 `fanhe-sync-watch`：登录触发 + 每分钟重复，`MultipleInstances=IgnoreNew`
- node 进程由调度器托管，心跳龄通常 < 60 秒
- 日志：`tools/collector/data/sync-watch.log`（>5 MB 轮转一份，已进 .gitignore）
- 自愈实测两次：外部 kill 后 85 秒内恢复；`0xC000013A`（控制台中断型）退出后由下一次重复触发拉起

## 三、排障顺序

1. `node scripts/doctor.mjs` —— 先看有没有阻断项，有就按结论处理
2. 阻断项对应动作：浏览器没开 → `shop-login.ps1 -Shop <code>`；登录失效 → 在采集浏览器里登录一次；端口不一致 → 改槽位或改库；库里没这家店 → 去绑定
3. 只有提示时不用动，等下一次采集窗口
