### 2.1 T4-01 的开工前置（三处决策 + 四条坑）

**三处决策（建议开工第一件事就定，写进实施记录）**

| # | 决策点 | 关键事实 |
| -- | -- | -- |
| D1 | 加载**构建产物**还是**开发服务器** | 任务定义写的是「加载现有前端构建产物」（`apps/web/dist`，已存在）。开发期可另设一个指向 `http://localhost:5173` 的模式，但**验收对象是产物模式** |
| D2 | 前端资源走 `file://` 还是内置静态服务 | **已核实**：`apps/web/vite.config.ts` 没有设 `base`，用默认 `/`。以 `file://` 直开 `dist/index.html` 时绝对路径资源会 404（白屏）。要么把 `base` 改为 `./`，要么起内置静态服务。**先验证再动手，别等打包完才发现** |
| D3 | Electron / electron-builder 版本 | 镜像已指向 npmmirror，二进制落工作区 `.cache/electron`。版本需与 Node 22 兼容 |

**四条坑（按出现顺序）**

1. **`onlyBuiltDependencies: []` 是第一个坑。** 该字段在 `pnpm-workspace.yaml` 里被**刻意置空**（针对 esbuild），而 `electron` 的二进制正是靠安装脚本下载的。**装 Electron 前必须把 `electron` 加进该列表**，否则 `node_modules/electron` 只有 JS 包装没有二进制，运行时才报错，且报错信息不指向根因。
2. **U 盘写入量。** 装完确认二进制确实落在工作区 `.cache/electron`（`ELECTRON_*_CACHE` 已在 `ws-env` 里重定向），而不是系统盘。
3. **资源路径。** 见 D2。
4. **包管理入口唯一。** 一律经 `infra/portable/ws-run.cmd`，裸跑 pnpm 会静默把 store 落到宿主机磁盘；并行调用会撞车，串行即可。

### 2.3 一处需要你拍板的验收口径（T4-02）

T4-02 要求「本机地址与远程地址的配置切换，两种模式均可用」。但**远程地址本身要到阶段五（T5-04 Tunnel）才存在**。因此 T4-02 的「远程模式可用」有三种可能口径，需选一个：

- **(a) 可配置即算**：只验证「改配置能切到远程 URL 且请求真的打到那个 URL」（用本地起一个假端点），不要求真远程。
- **(b) 指向阶段五**：T4-02 只做配置切换与代码路径，远程模式的**真实验收顺延到 T5-04**。
- **(c) 先搭一个临时远程端点**：成本最高，且阶段五大概率会重做。

建议 (a)：它把「切换逻辑」验掉，又不假装远程已经存在。
