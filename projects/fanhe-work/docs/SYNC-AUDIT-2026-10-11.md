三项实测结果。

### 1.2 链路 A 连接器，待人工授权

WorkBuddy 的 GitHub 连接器认证模式为服务端代管，MCP 端点是 `api.githubcopilot.com/mcp/`。本地磁盘上没有也不会有它的 token 文件。

| 测试 | 结果 |
| --- | --- |
| 身份识别 | 成功，账号 `dy00001` |

需要说明的是，这条链路对当前目标并非必需。它的用途是让助手通过 GitHub API 读写远端，而「访问目标仓库并同步其中数据」这件事由链路 B 已经完成。

## 四、下一步准备方案

### 4.1 目标

把项目从「依赖已修复但环境未就绪」推进到「可连续开发」，并启动阶段三的下一项任务。

具体判据有三条。数据库可连接且表结构就绪。四道门禁全部通过。T3-05 具备开工条件。

### 4.2 范围

范围内的动作分两类。

环境层面包含数据库重建、依赖完整性复验、完整门禁执行。

开发层面包含 T3-05 的任务定义确认、可复用结构盘点、接口与数据模型设计。

范围外包含阶段四的 Electron 外壳、阶段五的服务端化、连接器授权这类非阻塞项。

### 4.3 优先顺序

**P0 环境就绪。** 数据库重建与门禁验证必须先做。理由是后续任何开发都要在可运行的环境上验证，而当前数据库状态未知，依赖虽然重建但没有跑过完整测试。

具体动作有三步。启动 PostgreSQL 容器并等待健康检查通过。复制环境样例文件并填入签名密钥。执行迁移部署与种子写入，再用连接自检确认。

**P0 T3-05 纪要模型与接口。** 这是项目主线的下一项，也是阶段三三板块中的第二块。它的设计依赖权限点与导航体系，而这两者已经就位，无需等待其他工作。

**P1 文档入库。** 两篇报告提交进版本控制，让远端保持完整。

**P2 收尾清理。** 删除依赖重建备份，视情况处理连接器授权。

### 4.4 逐项准备清单

**数据库重建。** 参考 `projects/fanhe-work/README.md` 的数据库一节，以及 `docs/WORK-STATUS.md` 第 8.3 节。关键点有三处。数据库数据在宿主机命名卷上，不随介质移动，因此每次换环境都要重建。容器只绑定回环地址。启动迁移前必须确认容器健康检查已通过，否则会在初始化未完成时连库。

**门禁验证。** 四道依次为 `pnpm test`、`pnpm lint`、`pnpm typecheck`、`pnpm format:check`。前两项会先构建共享包。测试涉及数据库连接，因此必须在数据库就绪之后执行。浏览器级端到端验证另行执行，预期结果见 `docs/WORK-STATUS.md` 所述的通过数。

**T3-05 开工准备。** 任务定义见 `docs/DEVELOPMENT-PLAN.md` 第三章。三处现成结构可直接复用。数据表的归属隔离写法参照 `apps/api/src/launch/profiles.ts`，那里已跑通并有测试覆盖。界面三态参照 `apps/web/src/components/StateView.tsx`。前端数据层的两层结构参照 `apps/web/src/lib/launch.ts`，由 `api.ts` 负责拼地址，领域层负责包令牌与拆信封。

**新增数据表。** 需要在 `apps/api/prisma/schema.prisma` 追加模型并生成迁移。注意 `README.md` 提示的一条风险，迁移目录名的字典序与实际创建顺序可能不一致，现有四个迁移恰好满足依赖关系，新增迁移时要检查迁移之间是否真的独立。

**权限点。** 纪要相关的权限点已在 `packages/shared/src/permissions.ts` 中定义完毕，包括 `personal.note.read` 与 `personal.note.write`，四个内置角色的授权展开也已覆盖。种子脚本会从共享包读取，无需重复定义。

## 五、风险与注意事项

**迁移顺序风险。** 迁移目录名按字典序应用，而现有四个迁移的创建时间顺序与此不完全一致。新增迁移若引用更晚创建的对象，会出现依赖倒挂。处理方式是新增迁移前先确认它引用的对象在字典序之前已存在。

**共享包的构建依赖。** `packages/shared` 是构建型包，两个应用消费的是编译产物。根脚本的 `dev` 与 `build` 已包含先构建共享包这一步，直接调用子包脚本会跳过。开发期可另开终端进入监听模式。

**修复例程与本项目不匹配。** 工作空间机制的修复脚本中用 `npm rebuild` 处理依赖，那是 npm 的方案。本项目用 pnpm 的 isolated 链接器，换盘符后失效的是整棵依赖树的符号链接。这条已记入 `docs/PROJECT-SURVEY-2026-10-11.md` 第 8.2 节，建议补进机制文档。

**凭据的逐机属性。** git 凭据配置写在 `~/.gitconfig`，属逐机逐用户。换机或换 Windows 账户后必须重新配置，日期以 token 失效期为准提前处理。

**批量的删除保护。** 系统对批量删除有阈值保护，删除依赖备份这类含大量文件的目录会被拦截。清理时需要人工确认或分批执行。
