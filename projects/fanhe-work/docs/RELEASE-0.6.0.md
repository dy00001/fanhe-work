# 版本迭代方案 `0.6.0`

一版**把价格维护扩成操作台**的迭代。上一版（0.5.0）把三份台账搬进工作台、查价能搜能看，改价受口令保护；这一版把散在改价面板里的维护动作集中成一个四区操作台（分类 / 产品与价格 / 批量导入 / 变更记录），查价面板退回只读，数据来源从代码常量落进库。同时修掉案例库已有图片删不掉的问题，给放大预览加了左右旋转。

## 一、为什么是 `0.6.0`

| 候选 | 判断 |
| --- | --- |
| `0.5.1`（补丁） | 不合适。主体是新能力（维护台操作台、主类落库、整理能力、旋转），不是修复 |
| `0.6.0`（次版本） | **采用**。用户可见能力 + 升级需额外动作（重打安装包、重建容器） |
| `0.5.0` 原地重打 | 不合适。服务端多了 5 个迁移与一批接口，同号重发会让「装的是哪一份」无法判断 |

按项目既有的 0.x 约定，「破坏性变更」指**升级需要额外动作**。本版额外动作见 §3.1。

## 二、内容

### 2.1 价格与产品维护台（四区操作台）

价格维护集中到一屏，四区：**分类 / 产品与价格 / 批量导入 / 变更记录**。查价面板（首页卡片与 `/workbench/quote`）退回只读，改价、换图、停用都在操作台里做。

| 决定 | 原因 |
| --- | --- |
| 维护台是价格唯一在线入口 | 查价面板只读，避免「同一行价在两个地方都能改」造成真值分裂 |
| 识别与写库是两个接口 | `import/preview` 一行不写库，确认导入才 upsert；识别结果可以反复看而不产生副作用 |
| 导入是增量 upsert | 业务键由「来源 + 分类 + 名称 + 型号 + 规格」算出，重复导入不翻倍 |

### 2.2 主类落库

数据来源（销售查价 / 板式工艺 / 五金）从代码里的三个字面量搬进 `quote_sources` 表，可增删改。

- `code` 与 `ledger_prefix`（台账号前缀）创建后不可改：`code` 是每条产品业务键的第 0 段，改了等于把这一类下每条主键全换掉；`ledger_prefix` 印在纸质台账上。
- 删除判据含 `archived`（在售 + 已下架 = 0），由服务端算好 `deletable` + `deleteBlockedReason` 下发。
- 来源字段的 JSON Schema 只校验形状，取值域在库里，写路径用 `sourceExists()` 做真实校验。

### 2.3 分类与产品的整理

- **合并分类**：多选几个并成一个，产品整体改挂、编号不变；目标分类不存在时新建，`sortOrder` 取源里最小；源分类行删除。
- **产品折叠**：同一分类里多条折成一条。
- **删分类 / 删产品**：产品物理删除留整行快照进审计；删除边界（删到「这一类下面空了」）由服务端判断。

### 2.4 维护台体验

- **后台编辑口令入口**（仅超管可见）：口令原本只能从解锁弹窗设，而超管走直入路径看不到那个弹窗，「设 / 改口令」在界面上就没有入口。
- **产品图格可点**：有图显示缩略图、没图显示虚线框加号，点开行内展开「新增 / 更换 / 删除图片」。
- **表头固定 + 拖动排序**：分类、产品与价格、主类管理三屏。
- **来源配色一个出处**：统一到 `quoteSourceColor`。
- **新增与导入排最后**：新进来的东西一眼能看到。

### 2.5 批量导入修复

「服务器超时」与「切页丢结果」是三层叠加：JSON + base64 传输（4/3 膨胀）、客户端超时写死 90 秒、服务端 bodyLimit 只有 12MB。现在改原始字节 + XHR 直传，上传与识别分两段给真实进度，任务状态提升到模块级，切页回来结果还在。

### 2.6 案例库修复与旋转

- **已有图片可删**：根因是删除能力被绑到图片来源上，内置图在库里没有对应行。统一到 `DELETE /api/cases/items/:itemId`，上传图软删、内置图写隐藏行。
- **放大预览左右旋转**：纯视图状态，不改原图、不重新上传、不影响布局。

## 三、影响与风险

### 3.1 升级时必须做的动作

1. **跑迁移**。自 0.5.0 起新增 5 个：`20261103093000_add_quote_item_ledger_fields`、`20261103140000_add_quote_categories`、`20261103160000_add_quote_sources`、`20261103180000_add_quote_item_sort_order`、`20261103190000_add_case_item_deletions`。`migrate` 镜像必须重建。
2. **重跑 `db:seed`**（如有权限点变化；本版未新增权限点，`permissions` 维持 24 行）。
3. **重打并分发安装包**。前端改动是构建产物，不打新包装的是老界面。
4. **重建 `api` 与 `web` 镜像并 `--force-recreate`**，让版本号与产物生效。

### 3.2 会被用户感知的变化

- 报价查价页面的改价入口消失，改到「价格与产品维护」操作台。
- 数据来源可以自己增删改，不再是三个写死的标签。
- 分类能合并、产品能折叠、能删。
- 案例库里的已有图片（含内置示例图）可以删掉了，放大预览能旋转。

### 3.3 仍然存在的风险

| 风险 | 现状 |
| --- | --- |
| 维护台没有独立写权限点，写路径仍靠口令 | 沿用 0.5.0 的口令机制，超管直入、其余人凭口令 |
| 台账不是实时价 | 改价只改库，不回写 Excel |
| 搜索不做拼音 / 同义词 | 台账原文怎么写就怎么搜 |
