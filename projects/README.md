# projects

开发程序目录。后期所有软件项目都放在这里，每个项目一个子目录。

## 约定

1. 每个项目一个子目录，例如 `projects/my-app/`。
2. 一律从工作空间入口进入开发，环境重定向才会生效。

   ```
   infra\portable\ws-run.cmd <命令>
   infra\portable\ws-run.cmd -Shell
   ```

3. 项目内不要出现盘符。需要工作空间根目录时用环境变量 `WS_ROOT`。
4. 依赖、构建产物、缓存都由入口脚本重定向到工作空间内部，不要手工改到别处。
5. 本目录与 `infra/` 分属两类内容。`infra/` 是约束与基础设施，由机制维护；本目录是业务代码，由开发者维护。

## 为什么与 infra 分开

`infra/` 的内容随机制演进，变更频率低但影响面大。本目录的内容随业务迭代，变更频繁。物理分开可以降低在改业务代码时误动机制文件的概率，也让审计与备份的边界保持清晰。
